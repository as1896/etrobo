# app 中心システム図

## この文書の目的

この文書は、ETロボコン開発で最も触ることが多い app 配下を中心に整理したものです。

全体システムの中で app がどこにいるのかを見たうえで、
app の中をさらに機能単位に分けて理解できるようにしています。

---

## 1. app 全体を俯瞰するシステム図

sample_c5_study を例にすると、app 配下は次のように捉えると分かりやすいです。

```text
┌──────────────────────────────────────────────────────────────┐
│ app ディレクトリ                                             │
│  sample_c5_study/                                            │
│                                                              │
│  app.c            : 動作全体の流れをまとめる                 │
│  app.cfg          : RTOS に何をどう起動するかを伝える        │
│  app.h            : 優先度・周期・公開関数宣言をまとめる     │
│  LineTracer/      : 走行制御の中身                           │
│  TraceLogger/     : 走行データ記録の中身                     │
│  Makefile.inc     : この app のビルド追加設定                │
└──────────────────────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ app の外側の基盤                                              │
│  - TOPPERS/ASP3 RTOS                                          │
│  - SPIKE API                                                  │
│  - モータ・センサーのドライバ                                  │
│  - Athrill / シミュレータ                                      │
└──────────────────────────────────────────────────────────────┘
```

### app 内の責務分担

| 要素 | 役割 | 見るべきとき |
|---|---|---|
| app.c | 全体の流れ、開始停止、モジュール連携 | 挙動全体を変えたいとき |
| app.cfg | タスク構成、周期実行 | 周期やタスク構成を変えたいとき |
| app.h | 優先度、周期、宣言 | 基本設定を変えたいとき |
| LineTracer | 走るロジック | 制御則を変えたいとき |
| TraceLogger | 記録の仕方 | ログ項目や出力を変えたいとき |
| Makefile.inc | ビルド対象 | ファイル追加やビルドオプション変更時 |

## 2. app の実行構造

app は単一ファイルではなく、次の流れでまとまって動いています。

```text
app.cfg
  ├─ MAIN_TASK を定義する
  ├─ LINE_TRACER_TASK を定義する
  ├─ TRACE_LOGGER_TASK を定義する
  ├─ LINE_TRACER_TASK_CYC を定義する
  └─ TRACE_LOGGER_TASK_CYC を定義する

            ↓ RTOS が実行

app.c
  ├─ 初期化する
  ├─ スタート待ちする
  ├─ 周期タスクを開始する
  ├─ 停止入力を監視する
  └─ 停止後に再開待ちへ戻る

            ↓ 並行して動く

LineTracer
  └─ センサー値からモータ出力を決める

TraceLogger
  └─ 走行中の状態を記録する
```

ここで重要なのは、app.c が全部の処理を自分でやっているわけではないことです。
app.c はあくまで司令塔で、実処理は機能モジュールに分けられています。

## 4. 機能ごとのシステム図

ここからは、app を機能単位で分けて見ます。

### 4-1. 起動・待機機能

```text
app.c
  ├─ フォースセンサーを取得する
  ├─ LineTracer を初期化する
  ├─ TraceLogger を初期化する
  └─ スタート入力が来るまで待つ

関係するファイル
  - app.c
  - app.h
  - LineTracer/LineTracer.h
  - TraceLogger/TraceDataLogger.h
```

この機能の役割は、走行前の準備を整えることです。
ここではまだロボットを走らせず、走行モジュールが動ける状態を作ります。

### 4-2. 走行制御機能

```text
app.cfg
  └─ LINE_TRACER_TASK を周期起動する設定
        ↓
app.c
  └─ sta_cyc(...) で周期実行を開始する
        ↓
LineTracer
  ├─ カラーセンサー値を読む
  ├─ 目標との差を計算する
  ├─ 操舵量を決める
  └─ 左右モータ出力へ変換する
```

この機能は、app の中核です。
ETロボコンで走り方を変える場合は、最も手を入れる可能性が高いのはこの領域です。

### 4-3. ログ取得機能

```text
app.cfg
  └─ TRACE_LOGGER_TASK を周期起動する設定
        ↓
app.c
  ├─ TraceDataLogger_BeginRun()
  └─ sta_cyc(...) で記録を開始する
        ↓
TraceLogger
  ├─ センサー値を読む
  ├─ モータ状態を読む
  ├─ バッファへ蓄積する
  └─ 停止時に CSV へ出力する
```

この機能は、制御結果を観測するためのものです。
走行改善のための分析基盤として見ると分かりやすいです。

### 4-4. 停止・再開機能

```text
app.c
  ├─ Hub 右ボタンを監視する
  ├─ stp_cyc(...) で周期タスクを止める
  ├─ LineTracer_Stop() を呼ぶ
  ├─ TraceDataLogger_EndRun() を呼ぶ
  ├─ TraceDataLogger_DumpCsv() を呼ぶ
  └─ 次のスタート待ちへ戻る
```

この機能は、app を一回走って終わりにせず、
開始・停止・再開を繰り返せるアプリとして成立させています。

## 5. app の構造を機能でまとめ直した図

```text
                    ┌──────────────────────┐
                    │      app.c           │
                    │   全体の司令塔       │
                    └──────────────────────┘
                       │       │        │
          ┌────────────┘       │        └────────────┐
          ▼                    ▼                     ▼
┌────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│ 起動・待機機能 │  │ 走行制御機能     │  │ ログ取得機能     │
│ 初期化と待機   │  │ LineTracer       │  │ TraceLogger      │
└────────────────┘  └──────────────────┘  └──────────────────┘
          │                    │                     │
          └────────────┬───────┴─────────────┬──────┘
                       ▼                     ▼
               ┌──────────────────────────────────┐
               │ 停止・再開機能                   │
               │ 周期停止、モータ停止、CSV 出力   │
               └──────────────────────────────────┘
```

この見方をすると、app.c は処理本体ではなく、
複数機能を束ねるフロー制御層だと理解しやすくなります。

## 6. 実際の開発でよく触る順番

ETロボコンで app を改善するときは、次の順で考えるのが実務的です。

1. app.c で全体フローを確認する
2. LineTracer で制御ロジックを見る
3. app.cfg で周期実行のつながりを見る
4. app.h で周期や優先度を見る
5. TraceLogger で観測項目を増減する
