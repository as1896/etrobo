# ETロボコン シミュレーション環境 全体俯瞰図

## この文書の目的

この文書は、ETロボコンのシミュレーション開発環境を高い抽象度で俯瞰するためのものです。

ここで見たいのは、個々の関数や API の詳細ではなく、次の 3 点です。

- どの層が何を担当しているか
- どの設定ファイルがどこで効くのか
- 開発者が普段触るアプリと、その下の基盤がどうつながっているか

詳細な app 中心の図は、別ファイルの APP_SYSTEM_ARCHITECTURE.md に分けています。

---

## 全体像

この環境は、大きく 4 つのまとまりで見ると理解しやすいです。

```text
┌──────────────────────────────────────────────────────────────┐
│ 1. 開発対象                                                  │
│   sdk/workspace/<app>/                                       │
│   - app.c                                                    │
│   - app.cfg                                                  │
│   - app.h                                                    │
│   - アプリ固有モジュール                                      │
└──────────────────────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 2. 実行基盤                                                  │
│   - TOPPERS/ASP3 RTOS                                        │
│   - SPIKE API / EV3 API                                      │
│   - モータ・センサーのドライバ層                              │
└──────────────────────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 3. シミュレータ接続基盤                                       │
│   - athrill2                                                 │
│   - device_config.txt                                        │
│   - memory.txt                                               │
│   - vdev による UDP 通信                                     │
└──────────────────────────────────────────────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────┐
│ 4. 外部シミュレーション空間                                   │
│   - Unity 側の物理シミュレーション                            │
│   - コース                                                    │
│   - ロボット姿勢・センサー値生成                              │
└──────────────────────────────────────────────────────────────┘
```

要するに、開発者が書いた app がそのまま直接シミュレータを動かしているのではなく、
その間に RTOS、API、デバイス抽象化、Athrill の仮想デバイス層が入っています。

## 役割分担で見るシステム図

```text
[開発者が主に触る領域]
  sdk/workspace/<app>/
    ├─ app.c        : アプリの動き方を決める
    ├─ app.cfg      : タスクや周期実行を定義する
    ├─ app.h        : 優先度や周期などの定数を持つ
    └─ *.c / *.h    : 走行、判定、記録などの機能を分割実装する

               ↓ ビルドされる

[アプリを動かす基盤]
  Makefile.workspace
    ├─ 共通設定を読む
    ├─ app.cfg を解析する
    ├─ RTOS 用の生成コードを作る
    └─ asp バイナリを作る

               ↓ 実行される

[シミュレーション基盤]
  athrill2
    ├─ memory.txt でメモリ空間を用意する
    ├─ device_config.txt で接続設定を読む
    └─ UDP で外部シミュレータと通信する

               ↓ 接続される

[外部世界]
  Unity / ETロボコン用シミュレータ
    ├─ モータ出力を受け取る
    ├─ 物理演算を進める
    └─ センサー値を返す
```

## 時系列で見る全体フロー

### 1. ビルド時

```text
app ディレクトリ
  ↓
Makefile.workspace
  ↓
app.cfg と共通設定を読み込む
  ↓
RTOS 用コードを生成する
  ↓
asp バイナリを作る
```

この段階では、アプリのソースが RTOS 上で動く実行物に変換されます。

### 2. 起動時

```text
athrill2 起動
  ↓
memory.txt を読む
  ↓
device_config.txt を読む
  ↓
asp バイナリを読み込む
  ↓
main_task が開始される
```

この段階では、シミュレーション用の CPU 空間とデバイス接続が準備されます。

### 3. 実行時

```text
app
  ↓
SPIKE API / RTOS API を呼ぶ
  ↓
ドライバ層が仮想デバイス状態を更新する
  ↓
athrill2 が UDP で外部シミュレータへ渡す
  ↓
外部シミュレータが物理計算してセンサー値を返す
  ↓
app がその値を読む
```

## 設定ファイルの位置づけ

全体を見ると、設定ファイルは次のように役割が分かれています。

| ファイル | どこに属するか | 役割 |
|---|---|---|
| app.c | アプリ | ロボットのふるまいを記述する |
| app.cfg | アプリと RTOS の境界 | タスク、周期処理、起動関係を定義する |
| app.h | アプリ | 優先度、周期、公開関数宣言をまとめる |
| Makefile.inc | アプリとビルドの境界 | 追加ソース、オプション、依存関係を足す |
| sdk/common/Makefile.workspace | ビルド基盤 | アプリ全体のビルド手順を束ねる |
| sdk/common/device_config.txt | シミュレータ接続基盤 | Athrill の通信設定を与える |
| sdk/common/memory.txt | シミュレータ接続基盤 | 仮想 CPU のメモリ配置を定義する |

重要なのは、app.c だけでは環境は成立しないという点です。
実際には、app.cfg が RTOS との接続点になり、device_config.txt と memory.txt がシミュレータとの接続点になっています。

## 開発者の視点で見た「どこを触るか」

ETロボコンの開発では、通常は次の順で関心を持てば十分です。

```text
最もよく触る
  1. sdk/workspace/<app>/app.c
  2. sdk/workspace/<app>/ 以下の機能別モジュール
  3. sdk/workspace/<app>/app.h
  4. sdk/workspace/<app>/app.cfg

必要になったら見る
  5. sdk/common/Makefile.workspace
  6. sdk/common/device_config.txt
  7. sdk/common/memory.txt

通常は直接触らない
  8. SPIKE API / EV3 API 実装
  9. カーネル内部
 10. athrill2 の vdev 実装
```

つまり、普段の開発対象は app 配下ですが、その app がどの層に乗っているかを理解しておくと、
なぜこの設定が必要なのか、なぜセンサー値が来ないのかを切り分けやすくなります。

## 全体俯瞰としての要点

この環境は、抽象的には次の一文で表せます。

```text
アプリが RTOS 上で動き、API とドライバを介して Athrill の仮想デバイスへアクセスし、
その Athrill が外部シミュレータと通信して、ロボットとコースの状態をやり取りしている。
```

そのため、全体像は次のように覚えるのが実用的です。

```text
app を書く
  ↓
RTOS に載せる
  ↓
Athrill で実行する
  ↓
Unity 系シミュレータとつなぐ
```
